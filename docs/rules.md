# Rules of the road for univocity-tools

Bun/TypeScript CLIs for Univocity contract build, release and deploy
(Cart, deployer, deploy-web). These are this repository's load-bearing
invariants (`T#`). The platform rules (`P#`) are in
[forestrie/protocol rules/platform.md](https://github.com/forestrie/protocol/blob/main/rules/platform.md);
a rule marked `⤷ specialises P#` is that platform rule's concrete check
here. Agents load a one-line digest of both,
`.claude/rules/rules-of-the-road.md`, generated by `dox digest`.

Each rule has **Why**, a source link and **Enforced-by**. Versioning:
MAJOR removes or redefines a rule, MINOR adds one, PATCH rewords.

### T1 — Build every CLI on citty, with parse and execute split
Every tool under `apps/` uses citty. The citty command lives in `apps/`,
`parse*` in `packages/<app>/options.ts`, and `run*` in
`packages/<app>/main.ts`.
**Why:** argument parsing stays testable and apart from side-effecting
execution, which is the repo's core CLI contract.
[CLI conventions](agents/cli.md).
**Enforced-by:** lint:check:cli, review

### T2 — Give each authority its own verb
Each authority is its own verb (`deploy`, `create-log`, `register-grant`,
`delegate`); never collapse authorities into flag combinations.
**Why:** least privilege must be legible. Grant flags follow from the
verb, so a caller cannot over-authorise by mixing flags.
[devdocs ADR-0052](https://github.com/forestrie/devdocs/blob/main/adr/adr-0052-cli-authority-taxonomy.md).
**Enforced-by:** review

### T3 — Sign zero-config statements COSE-natively with key-derived identity
Default signing produces registration-free, key-derived identity (hex
`kid` for ES256, CAIP-10 for KS256), with no certificate or registration
dependency.
**Why:** the CLI must emit SCITT-compliant statements offline with no
setup.
⤷ specialises P11. [devdocs ADR-0055](https://github.com/forestrie/devdocs/blob/main/adr/adr-0055-statement-issuer-subject-identity.md).
**Enforced-by:** review

### T4 — Run subprocesses only through the documented policy
Start external processes only with `Bun.spawn` (argv array, no shell).
Run `doppler run` outside npm scripts, and give cross-repo `forge` its
checkout as `UNIVOCITY_ROOT`.
**Why:** ad-hoc shelling leaks secrets and breaks the cross-repo forge
contract.
[Subprocess conventions](agents/subprocess.md).
**Enforced-by:** lint:check:subprocess, review

### T5 — Keep deploy-web a neutral, EOA-only thin shell
deploy-web holds no Safe, console or deploy-orchestration logic. Safe
deploy lives in the deployer CLI, deploy-core and the mandate console.
**Why:** the neutral deploy path must stay provider-agnostic, and a
browser Safe flow is a separate product surface with its own threat
model.
[devdocs ADR-0060](https://github.com/forestrie/devdocs/blob/main/adr/adr-0060-inline-safe-deploy-in-mandate-console.md).
**Enforced-by:** review

### T6 — Consume published packages, not source links
Shared deploy logic lives in the published `@forestrie/deploy-core`.
Consumers outside this repository depend on the published package with
exact or transitive pins, never on source symlinks.
**Why:** neutrality and reproducibility. A source link hides which
version a deploy actually ran.
[devdocs ADR-0060](https://github.com/forestrie/devdocs/blob/main/adr/adr-0060-inline-safe-deploy-in-mandate-console.md).
**Enforced-by:** review
